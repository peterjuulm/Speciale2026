## Main finding

**The build path leaks through five channels, and the compiler flag closes
three.**

1. Source paths in the PDB. Closed by PathMap.
2. The PDB's path inside the DLL's debug directory. The length of that string
   shifts every address behind it, so two paths of different length change far
   more than the five identity fields. Closed by PathMap.
3. File-local type names from the regex generator:
   `<RegexGenerator_g>F<hash>__…`, where the hash is of the source file's path.
   The path has become part of the program's type system. Closed by PathMap,
   because Roslyn hashes the mapped path.
4. The Razor generator writes the absolute `.cshtml` path into the C# text it
   generates (`#pragma checksum`, `#line`), and Roslyn embeds the text verbatim
   in the PDB. **Not closed by PathMap**, because it is the generator's text, not
   the compiler's. Closed in Phoenix by deleting two unused template files; open
   for any project that uses Razor.
5. Two SDK-generated json files with the path in plain text, `spa.proxy.json` and
   `staticwebassets.runtime.json`. Written by MSBuild targets. Whether they are
   part of publish is decided in layer 2.

**`ContinuousIntegrationBuild` only works with git.** Microsoft's recommended
setting takes the source root from Source Link, which finds it with
`git rev-parse`. Without `.git` only the NuGet cache is mapped, and the path
leaks anyway. csc was handed `/pathmap:"/home/leos/.nuget/packages/=/_/"`
verbatim and nothing else. Whether a build is reproducible therefore depends on a
file that is not part of the source. The explicit PathMap rooted in the props
file's directory works regardless.

**Two generators, two answers.** The regex generator follows PathMap, the Razor
generator does not. Same vendor. Determinism is not one setting, it is a decision
every component in the build has to have made. Every source generator in the
dependency tree is a potential path leak, and the compiler flag does not cover
them. That connects layer 1 with the dependency part in a way we had not planned.

## Lessons that belong to no single experiment

- **Restore is part of the build.** `obj/` holds both restore output
  (`project.assets.json`) and compiler output. "Clean" means "restore again". A
  green layer 1 implicitly claims that the graph resolves the same twice; that is
  only measured from a warm cache.
- **Two SDKs can carry the same name.** Arch's and Microsoft's 9.0.120 sit side
  by side, and `dotnet --info` alone does not say which one ran. The environment
  block records the hash of `csc.dll` for that reason.
- **Publish is per program, build is per project.** WebAPI and
  BackgroundJobExecutor are the two roots; ApplicationCore and Infrastructure are
  copied in under both. Four assemblies are compiled, ~300 are copied.
- **Docker and zip use different runtimes.** The Dockerfile publishes
  `--self-contained false` (runtime from the `aspnet:9.0` image), the release zip
  `--self-contained true` (runtime from NuGet). The reason given in the
  Dockerfile is disk space on the CI runner, not reproducibility.
- **Copied files keep the package's timestamp.** In the release directory
  `ApplicationCore.dll` is from yesterday and `BouncyCastle.Crypto.dll` from four
  years ago. The zip format stores both. That is layer 4's expected breakage,
  seen before it is measured.
- **Branch and lab are two things.** Fixes are committed on
  `thesis/reproducible-builds` in a worktree; measurements happen in an rsync
  without `.git`, because the SDK otherwise embeds the HEAD commit. The order is
  always measure, fix, measure.

## Craft that worked

- One run = clean + restore + build. The first attempt with "restore once, build
  twice" failed with NETSDK1004.
- `dotnet build` takes one project. Two roots are chained with `&&`.
- `DOTNET_ROOT` and `PATH` are set explicitly inside reprotest's `-c`, or you hit
  the Arch package.
- `dotnet msbuild -getProperty:PathMap -getItem:SourceRoot` shows what MSBuild
  *would* give csc, without building. `-v:n` shows what csc *got*.
- `experiments/pdbdump`: 60 lines of C# with System.Reflection.Metadata that dump
  the PDB's document table and embedded sources. Found the last byte on one diff
  where diffoscope's 450,000-line hexdump could not.
- The artefact pattern in reprotest is kept to our own DLLs, PDBs and json. The
  log fell from 453,927 to 19,381 lines, and the diffoscope time with it.

## Corrections to earlier wording

- **"Channel 3 is closed by PathMap" was the expectation after run 1, and it
  held.** But "channels 1-3 are closed at once" underestimated the count: there
  were five, not four.
- **"PathMap closes the path axis"** held on empty-class 14/9, a project with
  no generators and no Razor. On Phoenix it took PathMap *plus* a code change.
- **The 9/9 note's "the compiler's identity appears only in the PDB"** still
  holds. But the path appeared in the DLL, via the debug directory, and the type
  names appeared in the DLL's metadata. Those are two different leaks.
